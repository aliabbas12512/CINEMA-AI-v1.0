# Setup

## Requirements

| Component | Version | Notes |
|---|---|---|
| Node.js | 20.11+ (22 LTS recommended) | `tsx` runs the worker; scripts use `--env-file-if-exists` (Node ≥ 22.9) |
| PostgreSQL | 14+ (16 tested) | Any Postgres, including Supabase Postgres |
| Redis | 6.2+ (7 tested) | BullMQ queue + rate limiting. Use persistence (AOF) in production |
| FFmpeg / FFprobe | 6.x tested | Must include `libx264`, `aac`, `libass` (for burned-in subtitles), `loudnorm`, `sidechaincompress` |
| Fonts | Noto Nastaliq Urdu / Noto Naskh Arabic | Needed only for *burned-in* Urdu subtitles (`fonts-noto-core` on Debian/Ubuntu) |

### Install FFmpeg

- Ubuntu/Debian: `sudo apt-get install ffmpeg fonts-noto-core`
- macOS: `brew install ffmpeg`
- Windows: install a full build (gyan.dev / BtbN) and set `FFMPEG_PATH`/`FFPROBE_PATH`

Verify: `ffmpeg -hide_banner -filters | grep -E "loudnorm|sidechaincompress|subtitles"`.

## Local development

```bash
cp .env.example .env
openssl rand -base64 48            # paste into SESSION_SECRET
docker compose up -d postgres redis
npm ci
npm run db:migrate
npm run dev                        # http://localhost:3000
npm run worker                     # second terminal
```

Create an account at `/signup`, open **Providers** to confirm configuration, then **Create New Video**.

## Database

`DATABASE_URL` points at Postgres. Migrations are plain SQL in `drizzle/` (generated by
drizzle-kit from `src/server/db/schema.ts`) and applied with `npm run db:migrate`.

**Supabase:** use the project's Postgres connection string (a direct or session-mode connection
is recommended for the long-lived worker and for running migrations) and set `DATABASE_SSL=true`. Migration
`0001_enable_rls.sql` enables Row Level Security on every table with no policies, so the
Supabase `anon`/`authenticated` roles (PostgREST) cannot read or write anything; the app
connects as the table owner and enforces per-user authorization itself.

To change the schema: edit `schema.ts` → `npm run db:generate` → commit the new SQL → `npm run db:migrate`.

## Storage

- `STORAGE_DRIVER=local` — files under `STORAGE_LOCAL_DIR`, streamed only through the
  authenticated `/api/assets/:id` route (supports HTTP Range for video seeking). Web and worker
  must share the same directory (same host or shared volume).
- `STORAGE_DRIVER=s3` — any S3-compatible bucket (AWS S3, **Supabase Storage S3 endpoint**,
  Cloudflare R2, MinIO). Keep the bucket **private**; downloads use presigned URLs valid for
  `SIGNED_URL_TTL_SEC`.

Supabase Storage (per Supabase's "S3 Authentication" guide): create a private bucket, enable the
S3 protocol and generate an access key pair under *Storage → Configuration → S3* (server-side only:
these keys bypass RLS), then set `S3_ENDPOINT=https://<project_ref>.storage.supabase.co/storage/v1/s3`,
`S3_REGION` to the region shown on that page and `S3_FORCE_PATH_STYLE=true`.

Layout:
```
projects/{project_id}/characters/   character reference images
projects/{project_id}/locations/    location reference images
projects/{project_id}/shots/        keyframes, provider clips, lip-synced clips
projects/{project_id}/scenes/       480p scene previews
projects/{project_id}/audio/        voice lines, music cues, SFX, final mix
projects/{project_id}/subtitles/    .srt / .vtt (Urdu + English)
projects/{project_id}/final/        final MP4 + thumbnail
```

## Redis

Use a persistent Redis (AOF) so queued jobs survive restarts. A managed Redis (Upstash with
TCP, Redis Cloud, ElastiCache) works; BullMQ needs `maxmemory-policy noeviction`.

## Providers

See [PROVIDERS.md](PROVIDERS.md). After setting keys run:

```bash
npm run providers:check
```

It calls each provider's real API (account, model availability, Urdu voices) and exits non-zero
on failure.

## Production deployment

Two processes from the same codebase/image:

1. **Web** — `npm run build && npm start` (or the Docker image's default command). Stateless;
   scale horizontally behind HTTPS. Set `APP_URL` to the public origin (used for CSRF origin checks).
2. **Worker** — `npm run worker` (Docker: `npx tsx src/worker/index.ts`). Needs FFmpeg, CPU and
   scratch disk (`WORK_DIR`; a 10-minute 1080p project needs several GB while rendering).
   Scale by running more workers and/or raising `WORKER_CONCURRENCY`.

Docker:

```bash
docker compose up -d --build        # postgres, redis, web, worker
docker compose run --rm web npm run db:migrate
```

Checklist:
- `NODE_ENV=production` (secure cookies), HTTPS termination in front of the web app
- `SESSION_SECRET` ≥ 32 random chars; rotate by invalidating sessions
- `ALLOW_SIGNUP=false` after creating accounts if the studio is private
- S3 storage with a private bucket for multi-host deployments
- Health check: `GET /api/health` (database + Redis)
- Logs are JSON (pino) on stdout; ship them to your log stack

Serverless platforms (e.g. Vercel) can host the **web** process; the **worker** must run on a
long-lived host/container with FFmpeg (Fly.io, Railway, ECS, a VM, Kubernetes).
